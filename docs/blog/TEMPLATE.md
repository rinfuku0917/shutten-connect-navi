# 記事の書き方

このファイルは、SEO記事を書くときの型です。1本目は
[キッチンカーの出店料の相場](food-truck-fee-guide.md) が実例です。

書いたら `npm run blog:sql -- docs/blog/<slug>.md` でSQLを作り、
Supabase の SQL Editor で流す。下書きとして入るので、
管理画面で確認してから公開ボタンを押す。

## 守ること

- **数字は必ず自社のデータから出す。** 他社記事の相場を引き写さない。
  募集中の案件・登録している出店者は、他のサイトが持っていない一次情報。
  出した数字には「2026年9月2日時点」のように集計日を添える
- **見出しは h2（`##`）と h3（`###`）だけ使う。** h1 は記事タイトルなので本文には書かない。
  h2 は目次に出る。h2 を飛ばして h3 を置かない
- **本文の最初に結論を置く。** 検索から来た人は答えだけ知りたい
- 内部リンクは実在するページにだけ張る。`/places`、`/places?pref=東京都`、`/register` など。
  募集終了した案件へは張らない
- 「よくある質問」の章を置くと、その中身がそのまま検索結果のFAQとして扱われる
  （`app/lib/postBody.ts` の `extractFaq`）。h3 を質問、その下を答えにする
- キーワードを不自然に繰り返さない。`AGENTS.md` の「SEO実装ルール」に従う

## 章立ての目安

```
（導入）検索した人の疑問と、この記事の結論を3〜5行で

## 前提の整理          ← 用語や選択肢の説明
### 選択肢A
### 選択肢B

## 【実データ】…       ← 自社データ。この記事のいちばんの価値
### 切り口1
### 切り口2

## どう判断するか       ← 読者が自分の場合に当てはめられる基準・計算式

## 見落としやすい点     ← 費用、条件、リスク

## よくある質問         ← h3 が質問。4〜6問
### 質問1
### 質問2

## まとめ              ← 箇条書き5行以内 ＋ 登録への導線
```

## 書き終えたら

1. `docs/seo-keywords.md` の該当行のステータスを「公開」に更新する
2. その記事が同時に満たすキーワードがあれば、その行にも同じ記事を書く。
   同じ内容で2本書かない（重複コンテンツになる）
